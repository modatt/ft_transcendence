The backend utilizes **PostgreSQL 16** (Debian Bookworm) via the official Docker image to ensure a secure, optimized, and easily maintainable database environment. To adhere to strict security best practices, no passwords or credentials are hardcoded in the configuration files; instead, all sensitive data is securely injected at runtime using **Docker Secrets** stored in the `.secrets/` directory, and the database runs on an isolated internal Docker network to prevent direct external access.

To test if the database connection is working correctly, you must interact with it from within the container since port 5432 is intentionally not exposed to the host machine. First, open a shell inside the running container using `docker exec -it RemoLab_db bash`, then connect using the `psql` command: `psql -U <your_db_user> -d <your_db_name>` (you will be prompted for the password stored in `.secrets/db_password.txt`). Once inside the `psql` prompt, you can verify the connection is fully operational by running commands like `\l` to list databases or `\dt` to list tables.

Container 1: Django - Handles business logic, OAuth2, 2FA, and API endpoints.
Container 2: PostgresSQL - Stores relational data, user profiles, and OAuth tokens.
Container 3: Redis - Django needs a channel layer to handle WebSockets and push live data to the frontend. Redis is the industry standard for this.
Container 4: Nginx (Reverse Proxy) - Handles SSL/HTTPS (mandatory for OAuth2), serves static/media files, and routes traffic to Django.
